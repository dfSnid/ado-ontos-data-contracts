# dp-orders

The Orders data product's Databricks Asset Bundle, generated by `dpi new-product`. It
reads `samples.tpch.orders`, which every Databricks workspace has, and builds the objects the
`orders` contract in `data-contracts` names:

| Object | Kind | Built by |
|---|---|---|
| `orders` | Materialized view | The Lakeflow pipeline `orders` (`src/pipeline/orders.py`) |

The bundle owns the code and the data, never the metadata. Comments, tags, grants and the
Certified badge come from the contract, through the publish pipeline in `data-contracts`. The
data quality rules come from the contract too: the pipeline applies them as Lakeflow
expectations (`@rules.apply(...)`), so a rule changes only through a contract pull request.

## Make it yours

1. `databricks.yml`: set the workspace host. Point `source_table` at your own table to build
   from real data.
2. `src/pipeline/orders.py`: the query. Its columns must match the contract's properties.
3. More datasets: add a function per object, each with `@rules.apply("<object>")`, and the
   object to the contract and the access file.

## Try it yourself

From checkouts of `data-contracts` and `dp-integration` beside this one:

```bash
../dp-integration/bin/fetch-rules.sh src/pipeline/contracts.txt ../data-contracts
databricks bundle validate -t local --profile <your profile>
databricks bundle deploy -t local --profile <your profile>
databricks bundle run build -t local --profile <your profile>
```

## Targets

| Target | Catalog | Used by |
|---|---|---|
| `local` (default) | `sales_dev`, schema prefixed with your name | You, to try a change |
| `dev` | `sales_dev` | `pipelines/deploy.yml`, after merge |
| `prod` | `sales_prod` | `pipelines/deploy.yml`, after the `orders-prod` approval |

## Pipeline setup (once)

- Create the Azure DevOps Environments `orders-dev` and `orders-prod`; add an
  Approvals check on `orders-prod`.
- Create the pipeline from `pipelines/deploy.yml` and name it `dp-orders-deploy`.
- Run it once by hand, then add it as a pipeline resource in `data-contracts/pipelines/publish.yml`
  (Azure DevOps cannot resolve a pipeline resource with no successful run).

See "Start a new data product" in the install guide for the whole order of a change.
